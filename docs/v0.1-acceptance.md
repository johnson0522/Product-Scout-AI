## 架构与行为

```text
Local Next.js UI / Route Handlers
  → owner-scoped Product API
  → Agent Gateway
  → AgentRuntimeFactory
  → ResearchWorkflowRuntime / application Coordinator
     → Search → bounded HTTPS Fetch → Source repository
     → Evidence / acquisition repositories
     → schema-submitted DSH reasoning → Claims / Findings / Quality
     → explained Opportunity scores → Report → 7-day plan
  → persisted Product Events → SSE replay / live delivery
```

- 使用既有 Repository / Domain 边界，没有把 DSH API 引入页面或 Route Handler。
- DSH 固定 `0.2.1-alpha.1`，无升级、无新增 Agent Framework。
- ResearchRun 终态先持久化，再发布终态事件；同一 Gateway 内串行写状态，
  重新检查当前状态，防止 cancel 与完成互相覆盖。丢弃终态后的迟到事件。
- 关闭失败/取消运行的活动步骤。Search/Evidence 事件经过 awaited sink。
- SSE 支持 Last-Event-ID，心跳时查询持久事件，弥补进程通知丢失；reader cancel 会清理资源。
- 用户约束进入 Search 和四个结构化推理操作，数据库中的原始 goal 保持原样。
- 生产每步最多采集 5 个结果、总计最多 20 个，仍受更低的 sources budget 限制。
  20 份最多 8,000 字符的页面摘录为 200,000 字符 synthesis envelope 留出余量。
  超大 Search excerpt / prompt 继续明确失败，不伪造或静默重写证据。
- Fetch 仅允许公开 IPv4 的 HTTPS，DNS 固定到 TLS 连接，拒绝私网/保留地址、重定向、
  凭证及自定义端口；默认总超时 10 秒、正文 1 MiB、文本 8,000 字符。
  页面失败保留原始搜索摘录，并发布明确的失败 tool event。
- Source 保存来源元信息；C2 Evidence 的 URL 和 acquisition 继续承担证据追溯与归属。
  没有改写旧 evidence 表/Repository，也没有新增 migration。
- 原生动态导入保留 SDK 的 import.meta 模块位置，消除 Next 打包破坏 SDK 路径解析的问题。
  该方案针对本地 checkout，未声称 standalone 镜像部署已验证。
- 本地单 owner、无登录，默认只绑定 `127.0.0.1`。拒绝非本地 URL、跨源/跨站请求；
  不能作为公开或多人产品的认证系统。React 仅按文本渲染来源内容。

## API Contract

所有路径属于本地配置 owner；未知/他人的 project/run 返回 404；非法 UUID 返回 400。
所有读操作禁用缓存；SSE 保留 no-transform。底层查询错误不伪装成 not-found。
基础服务错误使用通用信息，不向创建接口输出数据库/provider exception 原文。

| 方法与路径 | 请求 / 成功响应 |
| --- | --- |
| `GET /api/projects` | `{projects}` |
| `POST /api/projects` | `{name, description?}` → 201 `{project}`；ownerId 由服务器提供 |
| `GET /api/projects/:id` | `{project, runs}`；不返回 agent session/runtime metadata |
| `POST /api/research` | `{projectId, goal, constraints?}` → 201 `{researchRunId}`；后台执行 |
| `GET /api/research/:id` | `{researchRun}`；steps/status 与业务结果，排除 runtime identifiers |
| `GET /api/research/:id/evidence` | `{evidence, acquisitions, claims, findings}` |
| `GET /api/research/:id/report` | `{status, reports, opportunities, validationPlans}`；未产出时为空数组 |
| `GET /api/research/:id/events` | SSE；可选 Last-Event-ID；无私有 trajectory/隐藏推理 |
| `POST /api/research/:id/cancel` | 204；终态不可再次取消，409 |

JSON body 最大 16 KiB；project name 255 字符、description/goal 4,000 字符。
执行错误由 ResearchRun.failed / cancelled 和 Product Events 表达，201 不代表研究成功。

## Remaining Risks / 下一步

1. **阻塞：真实模型研究。** 按 README 配置 `DEEPSEEK_API_KEY`、`DSH_HOME`；
   `PRODUCT_SCOUT_OWNER_ID` 使用 UUID 并显式 `pnpm db:seed-owner`。密钥不能提交、不能通过聊天日志输出。
   通过本地 UI 启动一次真实研究，检查真实来源、竞品/痛点覆盖、引用准确性、评分解释和 7 日计划。
   未完成前，V0.1 总体验收不标 ACCEPTED。
2. **部署边界。** 无登录/多用户认证，无公网部署验收。Next/DSH 仍为仓库固定版本；
   当前结论不包含依赖安全升级或公开托管安全认证。
3. **进程生命周期。** 无 durable worker/restart recovery/跨进程 execution ownership；
   server restart 可能留下 running 状态，不自动重启或伪造失败/成功。
4. **取消与事务。** 已发出的数据库事务/网络请求可能在 cooperative cancel 后返回；
   不承诺回滚已采集 Evidence 或跨聚合 exactly-once。Report 与 Plan 仍为独立幂等写入。
5. **事件。** 状态和事件是分开的事务；终态通知失败时 UI 通过状态轮询恢复，
   但没有 outbox 保证，不能宣称绝不丢失 terminal event。
6. **来源。** Fetch 不支持重定向、IPv6、JS rendering、PDF；失败回退搜索摘录。
   来源真实性与模型语义判断仍需人工抽查，不能把 schema-valid 等同于事实准确。
7. **上下文预算。** 超大搜索摘录仍可能触发 synthesis prompt limit；这是明确 failed，
   不是完整采集/推理能力保证。外部 provider 可能限流或失败。

无需再次批准代码阶段；剩余的真实模型验收需要可用环境配置，当前无法凭空完成。
